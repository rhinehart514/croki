# 05 — Migration: what folds, what cuts, which bones get reused

> **SUPERSEDED PACKAGE FILE.** This migration plan is complete history, not a current task list. Use
> [FIRM-SPEC.md](../FIRM-SPEC.md) and [STATE.md](../STATE.md).

**Historical status:** superseded migration spec from 2026-07-02.

```
Cold open:    prefilled graph, strongest current testable path highlighted
              (exactly one lit in phase 1), weak links marked.
First spray:  broad and shallow across signals, market, product gaps, offers,
              channels, messages, proof, measurement gaps.
Run altitude: founder compiles a whole path; Drover decomposes it into tasks,
              assets, patches, gates, and measurement.
Gate:         visible inline checkpoint on outward/action edges, backed by
              action-level approval objects.
Scope:        write the north-star, mark the phase-1 slice — scan → spray →
              graph → highlighted path → inspect weakness → compile run →
              gate → staged execution → measurement contract.
```

This spec maps today's Drover onto the GTM graph and sequences the cut so `npm test` stays green and the app stays launchable at every phase boundary. It does **not** design the new surfaces — that is 02-canvas-interaction. Old → new only.

Two standing rules for every cut below:

1. **Migrate the invariant before deleting its host.** Several surfaces on the gut list are the *only* home of a harness invariant (the autonomy ladder, the role wall, idea-taste writeback). Blind-ripping the surface regresses the wall. Each such case is named in §4.
2. **The backend bone outlives the frontend surface.** Most of what dies is projection; most of what the graph needs already exists in `brain/src`. Delete UI aggressively, delete brain modules only when their last consumer is gone.

## 3. Phased cut order — shippable at every boundary

Each phase ends with `npm test` green and the browser loop verified. A phase may land across several commits, but no phase starts before the prior one's invariant migrations are proven.

**Phase 0 — foundations beside the old app (no user-visible change).**
Land the object-graph store + typed edges (01) and the spray/weakness derivations (03) as new modules with tests, plus an adapter that projects today's real state (channels, runs, people, claims, experiments, market objects, product truths) into graph objects. Nothing is deleted. Exit: the graph API returns a real prefilled graph for `~/Buffalo-Projects` with derived (not seeded) weakness labels.

**Phase 1a — the graph becomes the center; the leaderboard and board die.**
Mount the new graph canvas (02) as the default center branch in App. Delete: `GtmMapLens` + `gtmMapModel` + the `gtmMapGate` full-screen branch + the `gtm-map` summon card; `GroundLens`/`BeliefSpine`/`groundModel`/`boardModel`/`beliefSpine` and the `board` lens; dead code (`PeopleLens` branch, the four unreachable Product lenses, `lens-meta.ts`). *Gate exception:* the `gtmMapGate` branch is the current home of a paused run's review — it may not be deleted until phase 1b's inline gate is live; if 1a ships first, the old GraphCanvas gate bloom remains the interim gate host. Exit: open a product → prefilled graph, strongest path highlighted, weakness lens one click away.

**Phase 1b — inline gate; the monolith review hosts die.**
Introduce the action-level approval object (04) and mount `GateReview` on the gate edge. **First** migrate `GatePromotePanel` + `gatePromote` wiring (replay decisions, `canReleaseGate`, `promoteChannel`/`revokeChannel`) onto it and prove `autonomy-ladder.test.mjs` + gate tests green. **Then** delete the GraphCanvas gate bloom, the NodeEditor gate tab, and (if still present) the map gate host. Exit: a staged run pauses at the visible edge checkpoint; approve/edit/return, pattern approval, and promotion all work there; nothing sends without it.

**Phase 1c — cold open; the goal front door and drive theater die.**
Repoint `ProductEntry` to scan + spray → graph. Delete `GoalLauncher` and `OperatorDriveState` and their App branches; run/compose progress renders on the graph (spray populates live; compile lights the route). Cut the `TeamOnboarding` boot block. Exit: a stranger points Drover at a repo and sees a populated graph with a lit path in minute one (doctrine hard part 3) — no goal box, no 3-minute spinner theater.

**Phase 1d — compile replaces compose; the composer demotes.**
Wire "Compile run" on a highlighted path through the extended `compileRunFromPath` (04 §1.2 — spine reused, seven-section decomposition new). Delete the `compose_and_run` monolith path, `candidate-composer.mjs` + its endpoint + the dock candidates picker, `deriveChannelFrom` hand-drawn feeds, and the LibraryPalette/ComponentLibrary hand-placement palettes. Strip ComposerDock to command/lens driver (nav, ask-about-node, transcript). Fold `IdeaReview` → loose cards and clarity items → loose cards (writeback rule in §4 risk 3). Exit: the full doctrine loop — scan → spray → graph → highlight → inspect → compile → gate → staged execution → measurement contract → **founder-entered outcome ingestion** (00 Scope item 11) — runs end to end on a real repo.

**Deferred (north-star, explicitly not phase 1).**
Full interactive path editing and swap-mode UI depth; the full lens set (experiment matrix, revenue, product-gap as graph lenses); `InputsInbox` → External-domain cards; microproduct card → per-node action; full outcome ingestion breadth + promotion scheduling UI (`promote-motion` stays backend-only); `NodeEditor` modal retirement once card drill-down covers config; `ReferencesPanel` retirement once edge-following covers it; Terminal/Query/Web keep-or-cut review; the `channel` → `pipeline` identifier rename (still a no-op refactor, still deferred).

## 4. Risks — load-bearing things hidden inside surfaces being cut

1. **Autonomy ladder lives in the gate hosts being deleted.** `GatePromotePanel` (inside `gate/GateReview.tsx`) + App's `gatePromote` bag (replay decisions from the live decision map, `promoteChannel`/`revokeChannel`) mount today only via the GraphCanvas gate bloom and the GtmMapLens gate host — both slated for deletion. **Order is mandatory: migrate in 1b before deleting either host.** The typed-graph guard that rejects forging autonomy onto a gate node (`graph-operations.mjs`) and the explicit-founder-act-only rule must hold on the new approval object. Tests: `autonomy-ladder.test.mjs`, `gate-pattern.test.mjs`.
2. **The role wall rides the same bag.** `canReleaseGate` (via `canApprove` / `team-store.mjs`, resolved per session team in App) gates who may release. It is invisible for a solo founder, so a blind rip would pass local testing and silently open team gates. The new approval object carries `requiredApproval` — wire the role check there in 1b, and keep the TeamSpace settings tab that administers roles.
3. **Idea-taste writeback dies silently with IdeaReview.** `resolveOperatorIdeas` → `recordIdeaDecisions` (`feedback-ledger.mjs`) is how kill/keep verdicts teach the next round. When ideas become loose cards (1d), card keep/dismiss must write the same ledger records before the pause path is deleted, or the taste rail quietly loses its ideation signal. Test: `feedback-ledger.test.mjs` extended to the card path.
4. **Deleting OperatorDriveState can orphan live sessions.** App's session polling + `syncOperator` is what carries `pendingGate`, `pendingProposal`, and failure reasons to the UI. The center theater dies, but the polling and the blocked/failed surfacing must re-home (run node metadata + the demoted dock) *in the same change*, or a `running` session looks hung and a `blocked` one becomes undiscoverable.
5. **The wall itself during the compose→compile cutover.** Between 1b and 1d two staging paths coexist (old `composeGraphForChannel` runs, new compiled runs). Both already route through `assertGateWall` + `runGraph`'s gate pause; keep it that way — no temporary direct-execute shortcut, ever. `anti-cage.test.mjs` and the wall tests must stay green through every intermediate commit, and the gate resume path (`resolveOperatorGate` / `executeGraph` with `resumeRunId` reusing the exact staged items) must be preserved on the new approval object — re-running discovery behind the founder's back is a regression even if the wall technically holds.
6. **Boot, deep links, and URL sync.** `/projects/:id` routing, `activateProject` on boot, and the overview-vs-focus restore live in App's boot effect and `loadChannel`. The new center must keep the route contract or every reload strands founders on the entry screen.
7. **Board API consumers outlive the board UI.** `server.mjs` board/spine routes stay until GroundLens/BeliefSpine are gone (1a), then die with `getPipelineBeliefSpine`/`getPipelineIcpGrouping`. The weakness engine — a **new module adopting `board.mjs`'s derivation discipline**, not an extraction of its layer helpers (03 §3) — is built and proven *before* the route is cut, not after; `board.test.mjs`'s never-seeded cases port over as the weakness engine's regression floor.
8. **Microproduct's two-authorization deploy.** The invariant (ships only under two explicit founder authorizations) is enforced in the build/deploy path, not the summon card — but the card is currently the only entry point. Cutting the card before a per-node action exists doesn't break the invariant, it strands the capability; sequence it as fold-not-delete (deferred list).
9. **Anti-cage drift while building the palette.** The 01 node domains and edge types are a palette, not a taxonomy. The migration must not re-introduce a closed enum in validation code while wiring typed nodes/edges — extend `anti-cage.test.mjs` to the new graph store in phase 0, before anything depends on it.
