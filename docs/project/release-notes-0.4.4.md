# Croki 0.4.4 release plan

Croki 0.4.4 introduces an opt-in founder-mode foundation without turning the
ADE into a marketing suite.

## Native and Venture turns

The composer offers two explicit, one-turn behaviors:

- **Native** preserves the provider's normal behavior.
- **Venture** joins product reality, implementation, customer evidence, market
  direction, positioning, and distribution into one founder-facing judgment.

Venture is visible before send and resets with ordinary composer state. It can
inspect and implement inside the authority already granted to the Thread, but
external writes, publication, spend, and consequential positioning remain
founder decisions. The former Product and GTM choices remain readable on old
turn receipts but are no longer offered as separate modes.

## Founder-approved venture truth

`.croki/venture.json` is the small, Git-trackable constitution for durable
founder-approved truth: venture name, outcome, audience, promise, principles,
decisions, unknowns, and source references. Venture turns may read it; observed
evidence and agent conclusions never silently update it. Legacy
`.croki/context.json` can be read as migration input when no venture file exists,
without an automatic write.

## Venture evidence foundation

Croki begins the product-and-market foundation beneath the ADE without introducing
a marketing dashboard. Product behavior, customer evidence, market signals,
and distribution results can share one typed, bounded observation envelope in
ordinary Thread activity. Every observation retains source provenance and
read-only authority; adapter-private bodies stay out of Senses, and observed
claims do not become founder-approved project truth.

Canvas is not required for this path and remains an optional projection rather
than the 0.4.4 product destination. Initial source adapters are follow-up work.

## Parallel Threads beta

Enable **Parallel Threads** in **Settings → Beta**. An explicit request such as
“spin up three threads to investigate this and converge here” can then use the
selected provider's native delegation capability.

The current Thread remains canonical. Parallel work is projected into its
existing Workstreams item, which collapses lifecycle updates into running,
waiting, complete, failed, and stopped states. The provider waits for terminal
results and returns one synthesis to the current Thread. Croki does not add a
coordinator screen, task database, second conversation store, or automatic
delegation policy.

The beta defaults off and can be switched off without changing or deleting
existing Threads. Providers without native delegation continue as ordinary
single-Thread turns.
