# Croki 0.4.11 — Generative Thought Views

Status: built release candidate
Date: August 8, 2026

Croki 0.4.11 adds automatic visual thinking directly to ordinary Threads while
preserving the native ADE. When bounded project perception contains useful
structure, Croki places an interactive View immediately after the relevant user
message. When it does not, the Thread stays unchanged.

## Product result

- Views choose comparison, causal, temporal, evidence, experience, system,
  counterfactual, or possible-world structure from the question and sources.
- Every statement exposes observed, attributed, derived, inferred,
  hypothetical, contradicted, or uncovered status.
- **View basis** shows what the representation foregrounds, omits, and covers.
- **Reframe** changes the organizing logic without changing the bounded sources.
- **Use in next message** returns a visible founder-selected reference and
  stable source IDs; displaying or exploring a View never sends or changes
  provider behavior implicitly.
- Sparse, unavailable, invalid, or unsupported inputs add nothing instead of
  producing a generic summary or empty visualization state.
- Canvas is absent from navigation, Settings, commands, and new timeline
  actions. Historical Canvas data remains readable for compatibility only.
- Web, React Native, and native SwiftUI consume the same semantic product
  contract with interaction reduced honestly by client capability.

## Provider boundary

New turns no longer expose Product or GTM harness choices. Build and Plan remain
the native ADE interaction choices. Historical harness identifiers and receipts
remain readable for installed-state and wire compatibility.

Codex restores T3 Code's fixed session-host instructions for Default and Plan
mode semantics, actual structured-input availability, product-native Preview
routing, and runtime identity. Those instructions explain the host without
adding Croki application context, task strategy, workflow, persona, or
delegation policy.

## Publication gates

- Rendered desktop and narrow-width journeys still need inspection in an
  available application browser. This environment reported no controllable
  browser instances.
- The native SwiftUI target and its new compiler tests still need `xcodebuild`
  on a machine with full Xcode and an iOS simulator. This environment has only
  Apple Command Line Tools.
- Signing, publication, and production deployment remain separately owned
  release actions.
