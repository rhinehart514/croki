# Croki 0.4.8: Resume the right work

Croki 0.4.8 makes the 0.4.7 product easier to use every day. A founder can find
the exact file, code, or prior conversation they need, reopen the right Thread,
and continue without reconstructing the work as histories grow or branches
move.

0.4.7 established Application Sense, Concepts, checked-screen history, Preview
exploration, and release artifacts. It also exposed too much product machinery.
0.4.8 keeps the useful evidence and native work while collapsing `.croki` into
one application brief inside the ADE.

## Find the work

- The project file picker opens files by name from the existing command path.
- Project search finds code and content without leaving Croki.
- Conversation search finds prior work by what was said, not only by a Thread
  title.
- Sidebar search and durable, regeneratable Thread titles make the matching
  Thread easy to recognize and reopen.

These are retrieval paths into the same project and Thread model. They do not
become a new search workspace, knowledge base, or navigation system.

## Resume without reconstructing it

- Catch-up replay is bounded so an older Thread does not hydrate an unbounded
  database snapshot when it opens.
- Desktop contains renderer memory growth and recovers from renderer crashes
  without turning a temporary failure into lost work.
- A Thread with an open pull request stays active after its latest agent turn
  finishes.
- Dedicated worktrees follow intentional branch movement so the pull request
  remains attached to the Thread that owns it.
- Oversized pasted screenshots are compressed instead of discarding the
  founder's input.

## Make `.croki` one clear focus

- `.croki/application.croki` becomes the single repository-owned application
  brief: identity, released reality, and current build intent.
- The Thread header shows one compact released-to-building focus. Opening it
  reveals the application promise and current intent, with one action to open
  the source.
- The setup form, manifest inference, progress model, and active Concept scope
  disappear.
- Croki no longer creates Concept files or Concept worktree Threads from a
  dedicated control.
- Opening a `.croki` file uses the ordinary project editor. There is no
  generated Application, Concept, Release, or Venture view and no automatic
  panel expansion.
- Historical application JSON, Concept, Release, and Venture files remain
  bounded compatibility input so older repositories do not break.

The founder directs product work in the canonical Thread and judges the actual
files, Preview, Review, Git, and shipped result. The brief keeps those Threads
on the same application without asking the founder to maintain another
workspace.

## Return Preview to proof

Preview opens and checks the running product. The App, Component, and Idea tabs,
component catalog, generated alternatives flow, Keep/Combine/Discard bar, and
Beta setting disappear. Checked-screen history stays because it preserves real
evidence without creating another way to direct the build.

## Inherited maintenance

Upstream browser, terminal, provider, Preview, mobile, and interface fixes may
land with the sync when they are low-risk and proven. They are maintenance, not
equal product pillars or permission to expand the release.

## Explicitly out of scope

0.4.8 does not add another application-awareness layer, `.croki` kind,
dashboard, evidence system, background synthesis loop, prompt recommendation
surface, or Preview mode. It does not define a future major product direction.

The application observation and screen-reopening capabilities already present
in the 0.4.7 codebase remain supporting infrastructure. They are not the story
or expansion surface for this patch.

## Release proof

- a founder can find a known file, a code phrase, and a prior conversation from
  Croki's existing navigation;
- the matching Thread reopens with a durable title and bounded catch-up;
- renderer recovery preserves recoverable work instead of stranding the Thread;
- an open pull request remains active and linked after intentional worktree
  branch movement;
- an oversized screenshot paste remains usable;
- the Thread header shows the current `.croki` focus without setup, progress,
  or Concept controls;
- opening the focus reveals the declared promise and build intent and can open
  `.croki/application.croki`;
- a `.croki` file opens as ordinary source without changing the workspace size;
  and
- Preview opens running apps without a second ideation workflow.

Focused tests must cover every integrated fix, and the existing 0.4.7
application, Thread, Preview, Review, and provider boundaries must remain green.
The release adds no new top-level workflow or durable product noun.
