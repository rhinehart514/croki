# Product / GTM living venture

## Product call

Product / GTM opens as a changing venture, not a flowchart. It can hold Product truth, audiences, promises,
offers, motions, durable Product-model alternatives, exact agent work, unscalable founder actions, world-crossing
acts, and evidence returns at the same time.

No universal noun contains the work. Motion, campaign, release, mechanism, pipeline, branch, Thread, and Run are
used only when the underlying reality earns them.

## Current hierarchy

- The canvas derives one focal consequence path from the longest founder-authored relationship chain. Product,
  shared Product/GTM truth, and GTM are distinct territories inside the same graph, never separate canvases,
  columns, or fixed lanes.
- Every focal step advances left-to-right. Product sits above the shared causal center and GTM below it; curved
  arrows bridge vertical territory changes without reversing the mental reading direction.
- Current truth is solid and founder-adopted.
- Provisional Product models are durable, source-bearing, visibly distinct, and comparable.
- Tentative repository reads sit in a restrained provisional field beneath current truth rather than competing
  with the venture's adopted direction.
- Product capabilities and experiences open into repository-grounded feature detail. The whole-venture canvas
  promotes an exact feature only when it changes the focal path, owns live work, or receives market evidence;
  it never expands every feature into a backlog map.
- Live work attaches to the exact objects and alternatives it can change.
- Any outward action stops at an amber founder gate with its exact material and expected return.
- Returned evidence travels to the affected Product/GTM claims without inventing an interpretation.
- Selecting any node expands it in place. A Product alternative grows into its exact creates, updates, removals,
  drift conflicts, and selective founder merge without opening a detached side card.

Agents and connected resources remain compact composable material in the surface-owned rail. Contextual
conversation may open over the canvas; direct SDK coding controls stay in Work.

## Interaction contract

- Semantic zoom compresses broad portfolios without deleting canonical records.
- Search, minimap, direct selection, keyboard access, and return-to-context keep breadth reachable.
- A compact top-right map key distinguishes Product, shared truth, and GTM. **GTM workflows** puts adopted
  workflows first; selecting one unfolds its established trigger, agent/tool work, conditions, founder gates,
  outward actions, and evidence return on this canvas. Motions without those mechanics remain explicitly motions.
- Selecting a node reveals its two-hop causal neighborhood and quiets unrelated work without removing it.
- Solid curved arrows carry the focal consequence path. Curved dashed arrows carry dependencies, provisional
  joins, and attached Work; source-bearing return curves carry evidence. A restrained spectrum appears only
  where an edge crosses Product/shared/GTM territory. Concise relationship labels remain visible only where
  they explain a causal distinction.
- Nodes are draggable and their presentation positions persist. Agents, tools, and sources dropped on an exact
  node open scoped work there. Unsupported drops refuse visibly; layout never becomes truth.
- Founder edits are immediate and undoable. Agent inference remains provisional.
- Blue means direct action/focus. Amber means founder authority. Motion occurs only while causal work is live and
  has a reduced-motion fallback.

## Verified signature loop

The deterministic browser receipt proves:

```text
real venture truth
→ live agent work

```

explicit authority for provider spending and world-crossing execution.

## July 21 coherence correction

The rendered Buffalo venture proved that a connected graph can still be incoherent. The retired projection gave
every object equal weight, sorted by territory, stranded Runs at the bottom of the canvas, floated labels away from
their causes, and allowed compatibility types such as Pipeline to become founder-facing hierarchy.

The current projection instead derives a strictly left-to-right causal spine, separates Product, shared, and GTM
territories without introducing lanes, places supporting inputs at their affected step, stacks exact Work beneath
its subject, translates compatibility types into plain roles, and resets superseded canvas cameras while retaining
the founder's exact mode, selection, Thread, and draft. Direction, Product feature/capability, Product/GTM path,
market reality, route, market test, evidence gap, provisional read, Work, founder gate, and evidence use distinct
silhouettes, icons, ports, and edge treatments. Territory-crossing edges use the restrained spectrum.

Reference grounding for this correction is the live Buffalo Product/GTM model, the founder-supplied node-editor
reference, and the project's existing Control Room interaction record. Mobbin screen, flow, and deep-search calls
each returned connector errors during the pass, so no unavailable external screen was treated as evidence or
invented as a comparable.

## July 21 default-composition enhancement

The canvas now improves the default rather than adding a ceiling feature. Its deterministic projection derives a
readable causal chapter, applies Product/shared/GTM positional gravity, clusters connected material, compresses
non-consequential features into their owning Product object, attaches Work and founder gates locally, bundles
shared edge departures, and reflows only the neighborhood of an expanded node. Initial framing includes the
causal chapter, active work, and exact founder decisions rather than shrinking the whole portfolio into view.
Manual placement remains an override and never becomes semantic truth. The presentation camera resets once for
the new composition while retaining the selected venture object, Thread, draft, and mode.

No new canvas dependency or founder-facing preference was added. React Flow's current layout guidance lists
Dagre, D3 hierarchy/force, and ELK as external options; D3 force is iterative, rectangular collision needs custom
handling, and ELK adds a large configurable engine. Drover instead keeps a feature-local deterministic layout
because territory, authority, evidence return, semantic feature compression, and stable local reflow are domain
rules rather than a generic graph optimization problem. See https://reactflow.dev/learn/layouting/layouting and
https://reactflow.dev/api-reference/types/fit-view-options.
