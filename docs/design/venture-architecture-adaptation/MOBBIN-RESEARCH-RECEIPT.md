# Mobbin comparative research receipt

Decision researched: whether Drover should behave as a freeform whiteboard, a structured architecture map, or a composed spatial operating surface that gains structure only when something becomes consequential.

The research informed interaction and disclosure, not Drover's visual identity or domain model.

## Retained references

### Mural — selected canvas object

Reference: [Mural selected-object screen](https://mobbin.com/screens/912701ba-ec19-489a-b2c8-4e5475ad75ed)

- **Observed:** direct selection preserves the canvas and exposes contextual actions, but permanent tool rails and a long object menu dominate the surface.
- **Inference:** direct manipulation makes an open canvas predictable; tool abundance makes it feel like authoring software.
- **Transfer:** selection remains the universal gesture and contextual action appears near the object.
- **Reject:** permanent drawing toolbars, long generic object menus, and formatting-first creation.

### Fibery — converting text into an entity

Reference: [Fibery text-to-entity flow](https://mobbin.com/flows/fb654193-6023-4a16-ba18-a68abd309008)

- **Observed:** ordinary text can be written first and converted into a structured entity later while remaining in the same workspace.
- **Inference:** delayed structure protects expression while enabling operational identity when needed.
- **Transfer:** open concept first; explicit promotion later; preserve identity and position.
- **Reject:** database collection setup, type administration, and exposing schema fields during ordinary thought capture.

### Reflect — graph overview and selection

Reference: [Reflect map screen](https://mobbin.com/screens/0e1be504-3f40-4cd2-8968-091212a155e5)

- **Observed:** distant items reduce to compact marks and labels; selection reveals a small detail surface without abandoning the graph.
- **Inference:** spatial overview and local inspection can coexist without miniature full cards.
- **Transfer:** semantic reduction at distance and anchored selection detail.
- **Reject:** treating link density or automatic clustering as business meaning.

### Google Maps — scale-dependent representation

Reference: [Google Maps overview screen](https://mobbin.com/screens/f43e366d-db4e-4856-a5ab-91f82a11f4d9)

- **Observed:** visible features and labels change by scale; the product does not merely shrink the same representation.
- **Inference:** a large spatial world remains comprehensible when each altitude answers a different question.
- **Transfer:** camera-driven semantic zoom, stable landmarks, selective labels, and an explicit layer/focus fallback.
- **Reject:** consumer-map chrome, generic pins, and visual density unrelated to founder judgment.

### Airbnb — selected place in map context

Reference: [Airbnb selected map item](https://mobbin.com/screens/0c2cfd8e-e022-47dc-954f-3bd15e54ad28)

- **Observed:** a selected item reveals compact anchored detail while the surrounding map remains visible.
- **Inference:** founders can inspect meaning without entering a permanent inspector maze.
- **Transfer:** anchored detail surface, preserved context, clear selected state.
- **Reject:** uniform result pins and card/list duplication.

## Counterpattern

### n8n — operational graph with configuration

Reference: [n8n workflow editor](https://mobbin.com/screens/c9fc0f76-a1e5-43b8-9262-5c4670c4f4d8)

- **Observed:** the graph is executable and powerful, but ports, configuration panels, run controls, and workflow machinery dominate comprehension.
- **Inference:** making every connection executable turns the canvas into a machinery editor.
- **Transfer:** exact operational trace and explicit execution state only at inspection depth.
- **Reject:** executable generic edges, node-port grammar, permanent configuration panels, and machinery-first opening.

## Product-specific conclusion

Drover should open as a composed venture atlas, accept untyped founder material, and reveal one contextual path for making something operational. Semantic zoom changes representation by meaning. Selection expands a bounded trace in place. Operational machinery remains inspectable behind the architecture.

Mobbin does not establish keyboard, screen-reader, reduced-motion, dense-venture, stale/offline, or execution-coupling behavior. Those requirements come from Drover's authority and must be verified directly in the product.
