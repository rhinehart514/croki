Drover · ADE component design system · 2026-07-15

The parts, every state, warm paper.

Drover is a desktop workbench for a solo founder running a one-person holding company — you vibe code your go-to-market and a permanent AI crew does the work while you steer. The primary surface is an infinite canvas inside an Agent Development Environment: a conversation rail, the venture atlas as center stage, and one swapping inspector. This document is the component layer of that ADE — the exact tokens, and every founder-facing part rendered as a real specimen at each of its states, not a screenshot. The bar is a frontier-2026 surface that stands next to Cursor and Linear on craft, but is unmistakably Drover: ink on warm paper, muted green, one amber, nothing default-looking. The palette and shadows are lifted from the approved composite; the behavior follows the founder decision log. Six nouns, no seventh: venture · conversation · effort · teammate · capability · record.

Backs · Tailwind 4 · Base UI 1.6 · Motion 12 · CVA · Geist ■ standard density is the shipping default composite wins on look · decision log wins on behavior

Spacing rhythm & radii

Three spacing registers — never share a token across registers
  • Micro (2–8px): --s-0 2 · --s-1 4 · --s-2 6 · --s-3 8 — hairline gaps, dot-to-label, kicker spacing.
  • Component (10–20px): --s-4 10 · --s-5 12 · --s-6 15 · --s-7 20 — card body inset, region padding, gaps between card parts.
  • Section (28–64px): --s-8 28 · --s-9 44 · --s-10 64 — page rhythm, block separation. Never used inside a card.
  • Radii: --r-xs 6 chips · --r-sm 8 wells/inputs · --r-md 11 capability · --r-lg 13 effort/composer/inspector-draft · --r-xl 16 panels · --r-pill status chips.

What makes it Drover's — delogo

Cover the label and this is still Drover: an effort card reads like a page torn from a working notebook, not a Jira ticket. The mono kicker in founder words, the content title that never shows an ID, and the footer built as an instrument — status dot + plain state word + faces — is a specific refusal of the generic dashboard row. Implementation
  • Feature-local, custom React Flow node. Lives at ui/src/components/atlas/EffortNode.tsx (transforms AtlasBetNode). Not a shared primitive — it is one archetype used in one place; the 300-LOC ceiling applies, so split the draft-cluster and the footer into sibling files if it grows.
  • CVA variant shape: cva(base, { variants: { state: {idle, hover, selected, working, needs, receding}, density: {editorial, standard, detailed} }, defaultVariants: { state:'idle', density:'standard' } }). State and density are orthogonal — a needs card can be any density.
  • Not a button. The node is selectable via React Flow's own handling; the card is a <div role="button" tabindex> with keyboard select, or better, let React Flow own selection and expose data-selected. Faces are CrewFace (existing).
  • Zoom drives density (Phase 3), not a prop the founder sets: React Flow useStore(s => s.transform[2]) → editorial at low zoom, detailed at high. The density toggle in the composite was a mockup-round device, not a shipped control.

11 — Motion

Meaning-only motion, warm and settling

The register is calm and settling — ease-out, no spring-bounce on chrome, "soothe and orient, never perform." The frequency gate governs: anything the founder triggers dozens of times a day, or by keyboard, gets no animation. The named springs below are the whole vocabulary; build them once in lib/motion.tsx off lib/springs.ts and route every surface through them.

Layout re-fit glide

spring · stiffness 210 · damping 32 · mass 0.9

When the rail collapses, inspector opens, or the window resizes, the atlas re-fits its stage cell and cards glide to new positions — never teleport. Motion 12 layout animation. Ceiling 320ms. Triggered rarely → animation earns its place.

Card enter · staged materialization

opacity 0→1 · scale 0.96→1 · stagger ~90ms · ease-out 260ms

The signature: nodes born in sequence from the hub over ~2–3s while the thread narrates. Never from scale(0). React 19 useTransition stages the births. This is the one place motion is allowed to delight.

Focus dim

opacity 1→0.4 · scale 1→0.97 · ease-out 220ms

Selecting an effort expands it and the rest recede into soft depth-of-field — dimmed and shrunk, never hidden. The founder keeps the map. Reversible instantly on deselect.

Panel dock (rail / inspector)

soft spring · stiffness 300 · damping 30 · width track

Rail and inspector open/close on the softer spring (no bounce on a size change). The stage re-fit fires on transition end so the atlas follows the panel, not fights it.

Presence / acting pulse

CSS · 2.4s ease-out · expanding ring

The only always-on motion: a working teammate's dot, a live effort's kicker, an acting capability. It marks presence, nothing else. Drops to a static ring under reduced-motion.

Base UI 1.6 · which primitive backs what

primitive → component
  • Button (already wrapped, @base-ui/react/button + CVA) → composer send, inspector close, rail collapse, all tool buttons. One shared Button; the green send is a data-attr override, not a new variant.
  • Popover / Autocomplete → composer @-node reference, ⌘O venture switcher overlay, any anchored node menu. Base UI Popover with CSS anchor positioning — ephemera, never a docked panel.

CVA variant shapes (the contract per component)

variant maps
  • Effort: { state: idle|hover|selected|working|needs|receding, density: editorial|standard|detailed } — orthogonal; defaultVariants: { state:'idle', density:'standard' }.
  • Teammate: { presence: idle|working|asking, interaction: rest|hover|selected, stale?: true }.
  • Capability: { status: connected|disconnected|acting, interaction: rest|hover|selected }.
  • Gate: { status: clear|oneWaiting|manyWaiting|showingPayload|granted|unavailable } — no approve/reject props.
  • Hub: { mode: resting|composing|materializing|named }.
  • Message row: { kind: founder|teammate|activity|handoff }. Inspector: { content: closed|effort|draft|teammateWork|artifact|record|loading|empty }. StatusChip: { tone: living|quiet|needs }.
  • API minimalism: before any prop, ask if a className, a CSS variable, or a data-* handles it. Crew accent is a CSS var; density is driven by zoom, not a founder prop.

Shared vs feature-local (the 300-LOC doctrine)

where each lives
  • Shared (ui/src/components/ui/): Button, Input, Textarea, and the motion primitives (lib/motion.tsx + lib/springs.ts) — reuse is stable and proven. StatusChip promotes to shared once used in ≥2 regions (header + gate clear already qualify).
  • Feature-local (components/atlas/, components/firm/): the five node archetypes, the conversation message kinds, the inspector content views. These are one-place archetypes — do not prematurely abstract a shared "Card." Split by responsibility before 300 LOC (e.g. effort footer + draft-cluster as siblings).
  • Domain code stays clean (doctrine): node components import projection data, never brain internals. The six nouns are a presentation contract over existing storage — no parallel store (invariant §6).
  • Reuse before adding: CrewFace/CrewAvatar, CapabilityNode, ConversationHandoff, WallReviewDetail, GoalComposer, ConversationFeed all exist and are re-pointed, not rebuilt.
