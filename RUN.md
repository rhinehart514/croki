# Drover run contract

## Resume order

1. Read `AGENTS.md`.
2. Read `docs/FIRM-SPEC.md`.
3. Read root `DESIGN.md`.
4. Read `docs/STATE.md`.
5. Inspect `git status` and the relevant diff; preserve unrelated work.

## Invariants

- Electron desktop is the shipped product; browser is a deterministic harness.
- Work and Product / GTM are the only founder surfaces.
- Product and GTM are one changing system. Several motions and Product-model alternatives may coexist.
- First value begins from a real repository and the question “What are you trying to make true?”
- The selected Claude or Codex model remains the agent the founder talks to.
- A broad founder direction may authorize durable, revocable safe inward work; it never authorizes unrelated,
  destructive, outward, capability-expanding, or Product-truth promotion work.
- Current truth is singular. Source-bearing provisional interpretations are plural and durable.
- Only the founder selectively merges Product truth, executes outward actions, or ends founder-owned work.
- Unscalable work is first-class. Pipeline is used only for a literal throughput pipeline.
- Facts, evidence, interpretation, exact work, and world consequences remain distinct.
- Every Run retains participant/provider/model, origin, scope, subjects, session, worktree, cost, artifacts,
  verification, stopping condition, and exact world-boundary holds where available.
- Compatibility storage may remain read-only; it never dictates current UI or language.

## Completion

Report user-visible outcome and evidence before implementation detail. Run the verification gates in
`README.md`; then complete one real repository-to-evidence-to-selective-merge dogfood loop. Record only observed
proof in `docs/STATE.md`.
