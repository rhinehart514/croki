# Croki interface

The Electron interface is Croki's one founder surface.

## Thread spine

The permanent spine is direct Claude/Codex conversation with exact Project, Thread, Run, model, repository,
worktree, and return identity. At rest, conversation and its anchored composer own the center. Diff, files,
preview, terminal, browser, tests, comparison, evidence, and Review appear only when exact material exists.

## Canvas

Canvas is one optional contextual workbench view over the canonical semantic model. It projects source-backed
Product structure, dependencies, decisions, live work, outward actions, and returned evidence when those
relationships improve the current coding task. It is not another mode, conversation, dashboard, or coding shell.

Opening or hiding Canvas never changes the selected SDK model, Thread, transcript, repository/worktree, composer
draft, active attempt, or exact Review. A focused Canvas object becomes explicit context for the same composer.

## Interface rules

- Near-black neutral room; DM Sans for operating text; mono only for machine material.
- Conversation uses native coding-client geometry: compact founder turns, unboxed agent output, one scroll owner,
  and an anchored composer.
- Blue is action/focus; amber is founder authority; restrained texture marks provisional interpretation.
- Exact code proof, Product interpretation, market evidence, and founder consequences remain visibly distinct.
- Nodes remain compact readable pills. Exact material receives the larger Review space.
- Unsupported structured output preserves data but never renders raw JSON as the finished result.
- Agent-inferred changes remain provisional. Founder edits are immediate and undoable.
- No dead-end Map route, Product/GTM mode, Releases destination, or compatibility noun is founder-facing.
- Keyboard, 200% zoom, reduced motion, offline, dense data, interruption, and restart are first-class.
